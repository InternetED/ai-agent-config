## Engineering workflow

Use the smallest appropriate Ed Engineering workflow step:

- Ambiguous idea: `$ed-brainstorm`
- Settled conversation: `$to-spec`
- Accepted spec: `$to-tickets`
- Ready task: `$implement`
- Completed implementation: `$code-review`
- Reviewed changes: `$ce-commit`

Use `$grill-with-docs` between brainstorming and specification only when domain rules, constraints, or existing decisions need pressure-testing. The developer manages branches and worktrees. Do not push commits or open a pull request unless explicitly requested.
